# Quality profiles and gates

Recommended settings inherit through Organization Default, optional Team Profile and Repository Override. Store only changed settings as overrides. Existing complete legacy configurations remain explicit overrides. Administrator changes require CSRF, repository authorization and the current profile version. Each save creates an immutable `quality_profile_version` Record containing overrides, effective settings, actor and inheritance versions. Analysis snapshots capture resolved settings and gate hash; later configuration changes do not rewrite old analyses.

Use Code Quality → Rules & Profiles to create a team profile, assign it to a repository, change rule enable/severity/threshold, select BASE and inspect version history. Backend APIs: `GET/POST /api/code-quality/profiles/current`, `POST /profiles/team-assignment`, `GET /profiles/versions`. Team IDs are organization scoped. Team assignment is quality-policy association, not authorization membership.

Supported thresholds include cyclomatic and ProjectTrace cognitive complexity, function length, class span, file span (PT-QUALITY-013), nesting, parameters and duplication tokens. Gates evaluate NEW_CODE or ALL_CODE/OVERALL, imported changed-line coverage, source parser coverage, nesting and required parser languages. Additional conditions support finding counts filtered by rule/dimension/severity; numeric syntax metrics; coverage; duplication; and parser failures, with EQ/LT/LTE/GT/GTE comparisons. Responses include observed value, configured threshold, affected finding IDs/files, decision and remediation.

Missing measurements produce REVIEW_REQUIRED. Rule-based default failures remain advisory because production precision is unmeasured. An administrator can explicitly authorize a condition to block despite unmeasured precision; this choice is versioned and audited. Required-parser and measured coverage conditions may FAIL based on observed evidence. BETA/EXPERIMENTAL maturity is not a production qualification. Expiring accepted-risk exceptions exempt only the current unchanged review identity; material evidence changes reopen review.

Validation: inheritance, updates without copies, version immutability, stale versions, rule overrides, file thresholds, condition validation, all four result states and required-parser decisions are covered by owned tests. 47 profile/coverage/quality tests passed; frontend build passed.
