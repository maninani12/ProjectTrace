## Threat model and reviewed call graph

Assume attacker-controlled repository text exploits a syntax/parser dependency and obtains arbitrary code execution in that parser process. The application coordinator, immutable installed ProjectTrace/runtime files, Linux kernel/LSMs, libseccomp, and bounded IPC decoder remain trusted. Repository scripts, package installers, templates and builds are never executed.

The source/report containment claim does not include a compromised kernel, Python interpreter/core primitives, compromised trusted bootstrap/runtime code, arbitrary operator-installed plugins, HTTP framework vulnerabilities, archive intake or the coordinator's persistence/crypto layer. Raw-source parsers are separated from these explicitly named trusted components; no blanket all-parser isolation claim is made.

## Selected Linux contract

Linux defaults to `PROJECTTRACE_PARSER_ISOLATION=required`. Production rejects `development` mode and non-Linux fallback at parsing entry. Workers start with `-I -B`, a minimal fixed environment, root working directory and closed inherited descriptors. Imported source never determines executable/module, filesystem allowlist or environment.

The trusted bootstrap loads only installed parser code/resources before reading stdin. It does not import database/API/worker-service modules or inherit their credentials. HCL's default writable pickle/Lark cache is replaced with the identical grammar built without a filesystem cache. No source-dependent operation runs before controls are installed.

Landlock ABI **3 or newer** handles filesystem rights through TRUNCATE. Only installed parser/runtime files and required resources are readable; all filesystem writes/exec rights are denied, and there is no writable temporary directory. A seccomp **allowlist**, default EPERM, permits required memory/stdio/read-only runtime operations and three read-only prctl queries. Socket/network, fork/clone/exec, ptrace/process-VM/pidfd, namespace/mount, kernel privilege and filesystem metadata syscalls are not allowed. Metadata denial supplements Landlock, which alone is not a filesystem namespace. Capability effective/permitted/inheritable sets are zero, no-new-privileges is set, dumpability/core dumps are disabled, process creation is denied and RLIMIT_NPROC is zero. O_PATH opens are explicitly blocked because Landlock does not mediate them; readonly open flags and fcntl commands are constrained to avoid metadata or asynchronous-signal bypasses. These controls are irreversible within the worker.

Every actual worker must demonstrate filesystem read denial, socket denial, exec denial, metadata denial and O_PATH denial, then emit its bounded policy attestation **before** reading the untrusted input packet. Readiness/cache-only native entry also launches a real probe. No configuration flag alone satisfies readiness. Unavailable controls fail closed; Linux/containers must expose Landlock syscalls and libseccomp. No elevated namespace or SYS_ADMIN capability is requested.

Resource limits remain per helper and parent wall deadlines terminate only the owned process group. Parent pipe draining bounds stdout in memory and discards stderr; a flooding child cannot allocate unlimited parent output. Completed, scoped per-file packets can survive a later interruption, but unfinished files have partial diagnostics and no affirmative observations. A missing combined-native packet also fails secret, claim, and applicable IaC/API engine summaries; loss of observation cannot advertise a completed negative scan. Malformed/scope-invalid/unattested output is rejected. Packet replay cannot cross input paths or substitute source hashes. Ordinary parser syntax errors remain explicit partial/invalid coverage, rather than successful empty results.

Production analysis failures retain encrypted input and use a sanitized `PARSER_ISOLATION_*` diagnostic without publication. Coverage import failure is invalid/unavailable, never fabricated zero or successful coverage. Policy/version is included in parser signatures, invalidating old uncontained observation/checkpoint reuse while preserving historical snapshots. Cache hits retain existing no-source-read behavior where structural identity is already complete. Child component timings are measured and merged; overlapping helper/host durations are not added as wall time.

## Supported environments and prerequisites

- Supported enforcement implementation: Linux x86-64/aarch64, Landlock ABI 3+, seccomp filtering, libseccomp.so.2 and an immutable, secret-free installed runtime. Only actually executed architectures can be called qualified; current CI tests x86-64.
- Kernel/LSM and any outer container seccomp policy must allow Landlock creation/add/restrict calls and installation of a tighter seccomp filter. Missing, disabled or blocked facilities are failures, not permission to run unrestricted.
- Docker installs libseccomp2. The dedicated job additionally runs the built non-root image read-only, with network disabled, capabilities dropped, no-new-privileges and a PID cap, and proves a sentinel readable by the application cannot be read by its parser child. This is a runtime acceptance check, not merely a build.
- Windows/non-production development may explicitly use `PROJECTTRACE_PARSER_ISOLATION=development`; status is DEVELOPMENT_UNCONTAINED. Windows Job Objects/POSIX limits do not claim filesystem/network equivalence. Linux development without a supported kernel must make that explicit opt-in; production refuses it.
- Operator secrets, uploads, other tenant objects and writable storage must never be placed inside installed parser/runtime allowlist directories. Those directories must not be tenant writable. Parent application/coordinator compromise is outside this process boundary.

This coding host returns ENOSYS for Landlock and rejects nested user namespaces. Local security enforcement is therefore **NOT QUALIFIED**. Local development-mode regression results are algorithm evidence only. Dedicated GitHub/Linux and built-container evidence must actually pass before claiming those environments work.

## Archive-boundary continuation (qualification pending)

The green baseline at `2837b367c54218daa0f12f21bf08296fb4b0e42a` is preserved. Its archive exposure is being addressed on the same draft PR; prior green counts do not qualify these new changes.

`analyzers.archive_parser` holds the existing ZIP policy without database/crypto imports. Required-mode `repository_store.archive_items` now invokes an attested worker through `archive_transport`: the worker can request only bounded ranges of one already-authorized seekable stream. The coordinator decrypts at most 512 KB per request, without interpreting ZIP structures or zlib and without passing keys, object paths or storage descriptors to the helper. No new plaintext spool is created. Outputs are per-entry packets, validated for canonical paths, duplicate/count/path-metadata budgets, byte quotas, hashes and inert skip/link metadata. The existing checkpointed CAPTURING inventory cannot become analyzable after a worker interruption. A successful end marker and clean process exit are required.

The 10 MB legacy ZIP path also crosses the same sandbox, retaining its source/intake distinction. Its bounded base64 result budget is 32 MB to accommodate encoding of the original 10 MB source limit; native/IaC limits are unchanged. The streaming archive helper has a new explicit 512 MB address-space / 120 CPU-second / 150 wall-second budget, justified separately from short syntax helpers because supported archives reach 512 MB compressed / 2 GB declared uncompressed. Unsupported compression, traversal, links, corrupt entries and directory-before-decompression behavior retain the original policy. Giant-repository throughput remains unqualified.

Required CI adds encrypted streaming above 10 MB, host ZipFile/zlib prohibition, Unicode filenames, concurrent streams, real helper crash/timeout and all existing archive safety cases. These are real-kernel tests; local development algorithm tests are not security evidence. Coordinator lexical/classification/CODEOWNERS processing remains an explicit open scope; archive implementation alone does not close overall SEC-002.

The optional authorized `benchmark_repository_analysis --archive` path was also found to interpret ZIP directly. It now uses the same archive boundary, explicit sorted selection, bounded component accumulation and guaranteed generator cleanup. It adopts the production directory-first validation and compression-ratio limit of 200 (previous benchmark-only limit: 250); this deliberately tightens benchmark intake without changing production limits. Release-package creation/verification and synthetic benchmark ZIP writers operate on ProjectTrace-owned data and are outside untrusted repository intake.

First archive CI attempt (40156236949) passed 14 cases but the crash probe timed out: it was using the one-shot read-to-EOF protocol instead of the new stream handshake. The owned probe now consumes the streaming configuration before crashing; crash assertions remain strict, and malformed-stream output is additionally tested. This failed attempt is not counted as qualification.

### Supported ownership contract and uncertainty

The existing supported glob subset retains root/relative variants, directory suffixes, `*`, `**`, `?`, character classes, Unicode and multiple declared owners; the last matching supported rule wins. This is not full GitHub CODEOWNERS parity. Negation, escapes, traversal and missing-owner declarations are unsupported and are never treated as owner assignments. Their presence returns `PARTIAL_UNSUPPORTED_RULES` and explicit diagnostics, while a repository assignment remains metadata rather than inferred code ownership. The historical first-5,000-line limit is retained and now exposes `CODEOWNERS_LINE_LIMIT` uncertainty.

CODEOWNERS source is at most 512 KB; individual patterns at most 4,096 characters; a worker receives at most 100 targets and performs at most 500,000 rule/target comparisons. These deterministic work limits supplement the unchanged 512 MB / 25 CPU-second / 30 wall-second / 16 MB output boundary. Excessive work, crash, timeout, unavailable enforcement and malformed/scope-substituted output fail closed; they never become a successful negative ownership result or cache entry. Interrupted private generations remain unpublished and may recover through existing job fencing/replay.

### Independent privacy guard

`sanitization.py` contains a fixed scanner with no regex, glob, eval, import or user-supplied pattern language. Its passes move monotonically through at most 1,000,000 characters per string; metadata depth is at most 60 and nodes at most 1,000,000 per checked value. It masks the supported private-key, database-URL password, credential-assignment, GitHub-token and AWS-key forms and removes values under explicit sensitive keys, including nested containers. Ambiguous redacted-key collisions, cycles, invalid objects/non-finite scalars and excessive structures are rejected. Generic helper operations that return source/JSON data for authorized intake are distinct from metadata operations; source bytes are not rewritten before hashing/encryption.

The guard runs in the coordinator on metadata helper replies, streamed observation packets, cache reuse and record creation/update. Native cache schema/version/policy/hash and observation correspondence are checked before reuse/persistence; parser-selected paths/rules/timing/state cannot establish a different source/snapshot/tenant identity. Record ownership and all database/authorization controls remain coordinator decisions.

Intentional compatibility correction: the old regex redactor consumed a final newline in `token: <credential>\n`, producing only `[REDACTED ENVIRONMENT SECRET]`. The fixed scanner returns `[REDACTED ENVIRONMENT SECRET]\n`, preserving evidence line offsets. Original source hashes are unchanged; the independently redacted blob digest may differ. Other supported normal credential forms have exact pre-change parity tests. This is bounded privacy enforcement, not universal semantic secret detection or a guarantee against adversarially encoded/covert output.
