# Analyzer accuracy methodology

Run `python -m scripts.evaluate_accuracy`. The versioned result is `benchmarks/accuracy-hardening-v2.json`; corpus hash, parser signature, analyzer version, timestamp and Python version identify its inputs. The current evaluation contains **76 labeled cases in 38 rule/language/framework/tier groups**, covering code quality, reliability, SAST, secrets, IaC, claim extraction/verification, contradiction, drift, impact and owned advisory-cache SCA correlation. TP/TN/FP/FN, precision, recall, F1 and Wilson precision intervals are reported per group, never combined into a universal marketing accuracy score.

Tier 1 uses deterministic owned synthetic labels. Tier 2 contains four pinned public CPython/Django source files, retained as inert text with commit, hash and source URL in `benchmarks/accuracy-corpus/opensource/manifest.json`; license texts are included. This is a negative-only selected-rule slice, not a representative repository evaluation. Tier 3 uses owned framework-specific pairs (DBAPI, hashlib and DOMPurify). Tier 4 is unavailable: no approved anonymized/design-partner corpus has been supplied. No customer repository source is published in these artifacts or executed by the evaluation.

The initial measurement is preserved in `accuracy-hardening-v2-before-parser-fixes.json`. It exposed a Python eval false negative, JavaScript shadowed-eval false positive and skipped `.env` file. These code gaps were repaired. Label audit also found that an import-only FastAPI claim was wrongly expected to be VERIFIED; static construction is now the positive fixture, while a separate regression verifies import-only evidence remains INFERRED. The original and corrected corpora differ and must not be presented as an identical blind comparison.

The corrected 76-case evaluation observed no mismatches in those labeled slices. Each rule group has a small purposive sample; production precision and population false-positive rates remain **UNMEASURED**. Perfect results on a pair cannot qualify a rule for default merge blocking. The public negative-only examples cannot estimate precision or recall. SCA correlation labels do not measure upstream advisory completeness. Drift/impact labels cover selected explicit BASE transitions, not general semantic change recognition.

`GET /api/trust/accuracy` and Rule Health show bundled measurements and whether their parser/analyzer signature matches the running code. Human feedback is separate: latest confirmed/dismissed occurrence judgments are tenant/repository scoped, with actor/reason/time/rule/version/language/framework in underlying audit/review records. Voluntary dismissal fraction is not an accuracy estimate and never automatically disables a rule. Production qualification requires broader independent labels, representative framework/version coverage, reviewed false-positive causes and sufficient evidence; no rule currently meets that threshold from this corpus alone.
