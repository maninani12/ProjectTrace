# Deployment and validated runtime

The supplied Compose file remains a loopback-bound demo configuration using PostgreSQL 17, Redis 7, migrations, seed, API, non-root worker/scheduler and nginx frontend. Set generated POSTGRES_PASSWORD and ANALYSIS_INPUT_KEY outside source control. Do not silently upgrade database major versions against an existing volume. Docker/Compose builds and these exact image versions were not executed in this environment.

Actual service validation used official Alpine 3.24 packages in an isolated QEMU VM: PostgreSQL 18.6, Redis 8.8.0, Python 3.14.8 and the locked Celery 5.6.3 dependency set. A non-root prefork worker (concurrency two, read-only ProjectTrace source) passed real async admission, multiple tenants, duplicate delivery, graph/gate/Ask scope and forced-crash recovery. Earlier Windows solo workers additionally tested real broker shutdown/restart, encrypted retained input, queued cancellation, expiry and migration rollback/re-upgrade. VM endpoints were loopback-bound and use disposable validation credentials. Imported repository code never executed.

Production API/worker require consistent DATABASE_URL, REDIS_URL, JOB_MODE=celery, ANALYSIS_INPUT_KEY and explicit CORS origins. Run Celery beat: the shipped configuration schedules lease recovery every 60 seconds and expiry hourly. Validation used a two-second recovery schedule to observe natural 125-second lease expiry without changing lease timestamps. Recovery handles retained native FILE/ZIP inputs; GitHub/provider-specific recovery remains separate/partial.

Production readiness still requires TLS, federation/member lifecycle, managed secrets/key rotation, object storage/retention, backup restoration, image pinning/scanning, parser sandbox hardening, monitoring, sustained load/fairness/outage drills and incident ownership. No public deployment or cloud resource creation was performed. See [Final validation](../FINAL_PRODUCT_VALIDATION.md).
