# Upgrade from 1.6.0 trust foundations

This working-tree release preserves the authoritative Record/Evidence Graph and existing authentication, imports, snapshots, reviews and cloud/native functionality. It is an additive hardening candidate, not a completed enterprise certification. Keep the source ZIP's top-level folder named **ProjectTrace**.

Before upgrade, stop admissions/workers, record organization/user/repository/snapshot/review/audit/session counts and verify a DB + encrypted-content backup with separately retained keys. `scripts.recovery_bundle` supports local SQLite; managed PostgreSQL/object-store restoration must be verified in staging. Never seed/reset a customer database to upgrade it.

Run `python -m alembic upgrade head` with the installed operator environment. Additive migrations 0008–0013 add structural identities/occurrences, account/OIDC lifecycle fields, enterprise SCM scope, content inventories/parser artifacts, fair queue projections/latest heads and scoped graph expression indexes. Original domain records are not semantically rewritten. Large indexes may require a maintenance window; online PostgreSQL index-build qualification is unmeasured. Compare pre/post counts and `foreign_key_check` locally; perform corresponding managed database validation in production. Defaults keep existing users enabled and local login allowed. Existing sessions/reviews remain stored; ordinary session expiry still applies.

New streaming ZIP routes retain original legacy import routes. Unchanged parser observations are reused; gates and repository-wide correlations are recomputed. New inventories use encrypted content references and lazy source inspection. Historical inline source and small-input parser cache remain readable. Existing source is not automatically migrated to S3. New declared/human-corrected components affect future snapshots only. Existing repository IDs, grants and historical scopes are preserved.

Configure `SOURCE_BLOB_DIR`, encrypted scratch storage and a shared analysis key for API/workers. Local Compose shares `source-data`; the scheduler now receives the same database/key configuration. Celery workers must consume `native,large,scm,advisory,celery`, or use separately bounded worker groups. Pending admission and running ceilings are separate. In-flight cancellation is cooperative; retries and recovery use fenced leases. Old running jobs should be drained before switching worker versions.

OIDC internal deployments now require explicit `OIDC_ALLOWED_PRIVATE_CIDRS` and optional `OIDC_CA_BUNDLE_FILE`; `OIDC_PRIVATE_HOSTS` alone no longer permits private/loopback destinations. GHES uses per-connection provider/API/app/installation/secret/CA configuration. Tokens and endpoints supplied by repository/webhook text cannot select arbitrary network destinations. Production now requires PostgreSQL `sslmode=verify-full`, verified `rediss://`, explicit HTTPS origins and Celery. Use `*_FILE` mounts for protected secret delivery.

Unsafe downgrade is rejected when snapshots reference new content inventories or active typed queue claims remain. Do not bypass those checks. Restore a verified matching pre-upgrade DB/blob/key set into a fresh destination if rollback is required. Never delete historical reviews, snapshots or migrations to make older code start.

After upgrade, verify real organization sign-in, repository grants, fresh ZIP import, explicit BASE → HEAD comparison, finding history/reviews, quality profiles/gates, exception expiry/revocation, Engineering Changes, paged graph/source inspection, Trust & Coverage and disabled/unknown capabilities. Keep all customer fixtures inert. Review current benchmark reports and the 21 buyer questions in `ENTERPRISE_TRUST_VALIDATION.md`; production service and representative precision claims remain gated on actual evidence.
