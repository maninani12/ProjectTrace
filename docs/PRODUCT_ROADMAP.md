# Product constitution and execution status

The permanent product constitution is retained in `PRODUCT_CONSTITUTION.txt`; `PUBLIC_LANDING_SPECIFICATION.txt` records the public-experience request implemented in 1.4.0. They define the direction, not a claim that every future capability is complete. The core remains **claim → current evidence → explainable decision → human ownership → auditable action**. ProjectTrace owns its native analysis and does not require SonarQube or Wiz.

| Constitution phase | Current evidence and remaining scope |
|---|---|
| 0 — Trusted baseline | Existing source inspected; backend/frontend/build/browser/dependency checks pass. Accounts, repositories and history are preserved. Production image/restore checks remain open. |
| 1 — Core | Authorized import, immutable snapshots, job status, evidence, claims, verification, consistency, drift, impact, audit and deterministic Ask baseline work. Richer normalized schema/semantic extraction remain partial. |
| 2 — Code intelligence | Native Python AST and JS/TS/Java syntax metrics, exact duplicate bodies, new-findings scope, versioned profiles and gates work. Full type/symbol/CFG models and broader labeled precision remain open. |
| 3 — Application security | Modeled bounded Python flows, context-dependent hotspots and secret masking work. Complete cross-file/interprocedural taint, framework/sanitizer coverage and full OS parser sandbox remain open. |
| 4 — Supply chain | Supported npm/Python declarations, exact-version optional OSV, observed-license profiles and CycloneDX work. Full ecosystem/resolver coverage and comprehensive license conclusions remain open. |
| 5 — Infrastructure | Supported Terraform, CloudFormation, Kubernetes, Compose and Dockerfile declarations produce native evidence. Rendered plans/modules, full policy semantics and image scanning remain open. |
| 6 — Developer workflow | Snapshot-based PR/change analysis, unified findings, explainable gates, ownership, reviews and expiring exceptions work. Live GitHub/private-source/check-publication verification remains open. |
| 7 — Cloud | Static typed assets, identity/exposure declarations and actual-edge risk paths work. Bounded direct AWS read-only adapter is implemented but live proof is unverified; Azure/GCP, effective IAM and runtime/deployment correlations remain deferred. |
| 8 — AI depth | Authorized deterministic/full-text/graph retrieval works. External AI, semantic embeddings/vector retrieval and model synthesis are not configured. |
| 9 — Enterprise hardening | Tenant/repository ACLs, local Argon2 sessions, CSRF, audit, encrypted expiring queued input and bounded worker recovery work. OIDC/member lifecycle, managed storage/deletion, production restore, sustained fairness/capacity and incident operations remain open. |
| Permanent product understanding | 1.4.0 supplies the public page, 31-topic Guide, simple/technical explanations, glossary, product map, contextual help and first-import transition. Formal user research and exhaustive accessibility coverage remain open. |

Future work must preserve snapshot identities, authority boundaries, cache/profile provenance and historical failure records. Add a native capability with concrete examples, tests, security review, measured coverage, UI explanation and explicit limits before claiming it is available. Source should never be executed to make a marketing demonstration look complete.
